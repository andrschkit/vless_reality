# VLESS+Reality на 3x-ui — семейный VPN на своём сервере

Набор для развёртывания панели [3x-ui](https://github.com/MHSanaei/3x-ui) (Xray, протокол VLESS+Reality) в Docker на своём VPS:

- каждому члену семьи — свой ключ, QR-код и subscription-ссылка (подписка сама обновляется у клиента, если ты что-то поменял на сервере);
- переустановка на чистый сервер за ~10 минут из бэкапа;
- минимум ручной возни: `install.sh` ставит всё сам.

Домен не обязателен: Reality маскируется под TLS чужого сайта, панель и подписки работают по IP + секретный путь. Но проект умеет и второй режим — **мастер + ноды + домен**: одна панель управляет несколькими VPN-серверами, подписка каждого клиента содержит все сервера разом, а панель и подписки ходят по домену через HTTPS-прокси. Это схема «на вырост» и для случая, когда IP серверов периодически блокируются: см. разделы 11–12.

## Требования

- VPS с **Ubuntu 24.04 LTS** (рекомендуется; подойдут и Ubuntu 22.04 / Debian 11/12 — скрипты те же). Чистый образ, без предустановленных панелей (Plesk и т.п.).
- Хватит минимального тарифа: 1 vCPU, 1 ГБ RAM, 10 ГБ диска.
- Доступ по SSH с правами root.
- Свободный 443/tcp (на сервере не должно быть сайта на 443 порту).

## Структура проекта

```
docker-compose.yml   — описание контейнера 3x-ui (одинаково для мастера и ноды)
scripts/install.sh   — базовая установка на чистый сервер (общая часть)
scripts/install-master.sh — мастер «под ключ»: панель + домен + HTTPS + RU-фильтр
scripts/install-node.sh   — нода «под ключ»: стек + закрытая панель + RU-фильтр + API-токен
scripts/attach-node.sh    — подключить ноду к мастеру и клонировать на неё инбаунд (на мастере)
scripts/lib/xui-api.sh    — библиотека для API панели (CSRF, сессии, Host-заголовок)
scripts/ru-filter-rules.json — правила RU-фильтра (источник истины)
scripts/node-hardening.sh — закрыть панель ноды всем, кроме мастера (2053/tcp)
scripts/setup-web.sh — nginx + certbot (DNS-01 через Porkbun) + UFW на мастере
scripts/certbot/     — хуки porkbun-auth.sh / porkbun-cleanup.sh для DNS-01
scripts/backup.sh    — бэкап всех данных панели
scripts/restore.sh   — восстановление из бэкапа (переустановка)
scripts/update.sh    — обновление панели (бэкап + pull); cron запускает еженедельно
docker-compose.bot.yml — телеграм-бот семьи (только мастер)
bot/                 — код бота (aiogram): ссылки/QR, инвайты, семьи, статус нод
scripts/install-bot.sh — установка бота на мастере
```

## 1. Первичная установка

Скопируй проект на сервер (из PowerShell на своём компьютере):

```powershell
scp -r G:\projects\vless_reality root@<IP>:/root/vless_reality
```

Зайди на сервер и запусти установку:

```bash
ssh root@<IP>
cd /root/vless_reality
bash scripts/install.sh
```

Скрипт сам: поставит Docker, раскладывает проект в `/opt/3x-ui`, включит BBR и автообновления безопасности, настроит файрвол UFW (открыты только SSH, 443/tcp и 2053/tcp), повесит в cron еженедельное автообновление 3x-ui и запустит панель. В конце напечатает адрес панели.

## 2. Первичная настройка панели

1. Открой `http://<IP>:2053` и войди с логином/паролем `admin` / `admin`.
2. **Сразу** в «Настройки панели» (Panel Settings):
   - смени логин и пароль (раздел «Аутентификация»);
   - включи двухфакторную аутентификацию (2FA, Google Authenticator и аналоги);
   - задай **секретный базовый путь** (Web Base Path), например `/a9f3k7/`. После этого панель открывается только по полному адресу `http://<IP>:2053/a9f3k7/` — без пути отдаётся пустышка;
   - при желании смени порт панели с 2053 на свой. Тогда открой его и закрой старый:
     ```bash
     ufw allow <новый>/tcp comment '3x-ui panel'
     ufw delete allow 2053/tcp
     ```

> Названия пунктов меню могут немного отличаться между версиями 3x-ui — ориентируйся по смыслу.

## 3. Создание инбаунда VLESS+Reality

«Инбаунды» (Inbounds) → «Добавить инбаунд»:

- **Remark:** любое имя, например `family`;
- **Protocol:** `vless`;
- **Port:** `443`;
- **Transmission/Network:** `TCP`;
- **Security:** `REALITY`;
- **uTLS:** `firefox` — на российских каналах большое chrome-hello (~1800 байт) часто приходит обрезанным, и серверный Reality его не парсит; firefox-hello (~600 байт) проходит стабильно;
- **Dest (Target)** и **SNI:** сайт-маскировка, например `www.yahoo.com:443` и `www.yahoo.com` (см. ниже);
- ключи: нажми **Get New Keys** — панель сгенерирует пару сама;
- в списке **Clients** добавь каждого человека: `email` = имя (например `mama-phone`), UUID сгенерируется автоматически, **Flow:** `xtls-rprx-vision`.

Сохрани. Порт 443 уже открыт в UFW установщиком.

**Как выбрать сайт-маскировку (dest/SNI):** крупный зарубежный сайт с TLS 1.3 и HTTP/2, который не блокируется твоим провайдером. Проверенные примеры: `dl.google.com`, `www.yahoo.com`, `www.microsoft.com`, `www.samsung.com`, `gateway.icloud.com`. Не указывай сайты, которыми семья реально пользуется через VPN, — маскировка и трафик не должны совпадать.

## 4. Включение подписок (subscription) — самое удобное для раздачи

1. «Настройки панели» → «Подписки» (Subscription): включи, запомни **порт подписки** (по умолчанию обычно `2096`) и **секретный путь**.
2. Открой порт подписки в файрволе:
   ```bash
   ufw allow 2096/tcp comment '3x-ui subscription'
   ```
3. В списке инбаундов/клиентов появятся кнопки: скопировать ссылку, показать QR.

Каждому родному даёшь **его персональную** ссылку/QR. Плюс подписки: если ты поменял что-то на сервере (добавил сервер, сменил параметры), клиент жмёт «обновить подписку» — и всё подтягивается само, без пересылки файлов.

## 5. Приложения для родных

| Платформа | Приложения | Как подключить |
|---|---|---|
| Android | v2rayNG, Hiddify | «+» → добавить подписку по ссылке / сканировать QR |
| iOS | Streisand, V2Box, Hiddify | Импорт по ссылке или QR |
| Windows | v2rayN, Hiddify | Subscriptions → Add → Update |

Для не-техничных родных проще всего **Hiddify** — одинаковый интерфейс на всех платформах.

> iOS: часть VPN-приложений недоступна в российском App Store — может понадобиться Apple ID другого региона.

## 6. Бэкап

Вручную на сервере:

```bash
bash /opt/3x-ui/scripts/backup.sh
```

Архив складывается в `/opt/3x-ui/backups/` (контейнер останавливается на 2–3 секунды — для консистентной базы). Хранятся последние 7 архивов — неделя при ежедневном бэкапе (настраивается переменной `KEEP`, напр. `KEEP=14 bash backup.sh`).

Забрать бэкап на свой компьютер:

```powershell
scp root@<IP>:/opt/3x-ui/backups/3x-ui-*.tar.gz G:\projects\vless_reality\backups\
```

Автоматически, ежедневно (cron):

```bash
echo '17 4 * * * root bash /opt/3x-ui/scripts/backup.sh >> /var/log/3x-ui-backup.log 2>&1' > /etc/cron.d/3x-ui-backup
```

Бэкап храни не только на сервере — при переустановке сервера он понадобится снаружи.

## 7. Переустановка с нуля (новый сервер)

1. Скопируй проект на новый сервер и установи всё: `bash scripts/install.sh` (см. шаг 1).
2. Залей последний бэкап на сервер:
   ```powershell
   scp G:\projects\vless_reality\backups\3x-ui-<дата>.tar.gz root@<НОВЫЙ_IP>:/root/
   ```
3. Восстанови:
   ```bash
   bash /opt/3x-ui/scripts/restore.sh /root/3x-ui-<дата>.tar.gz
   ```

Всё вернётся как было: пользователи, UUID, ключи Reality, настройки панели.

> **Нюанс со сменой IP:** sub-ссылки содержат адрес сервера. Если у нового сервера другой IP — раздай родным новые ссылки из панели (один раз, через тот же мессенджер). Сами ключи и UUID не меняются. Если когда-нибудь купишь домен и повесишь подписки на него — даже этот шаг станет ненужным.

## 8. Обновление панели

Обновляется **автоматически**: cron раз в неделю (среда, 04:37) запускает `scripts/update.sh`, который сначала делает бэкап, затем подтягивает свежий образ (`docker compose pull && up -d`) и чистит старые слои образов, чтобы не забить диск. Расписание — `/etc/cron.d/3x-ui-update`, лог — `/var/log/3x-ui-update.log`.

Вручную (например, вышло срочное обновление Xray):

```bash
bash /opt/3x-ui/scripts/update.sh
```

Если автообновление станет не нужно: `rm /etc/cron.d/3x-ui-update`.

## 9. Если на сервере уже стоит Amnezia

Конфликтов по портам нет (Reality — 443/tcp, AmneziaWG — UDP-порт). Но UFW по умолчанию **закроет** UDP-порт AmneziaWG — открой его (порт смотри в приложении Amnezia):

```bash
ufw allow <порт>/udp comment 'AmneziaWG'
```

Так AmneziaWG останется запасным каналом рядом с VLESS.

## 10. Безопасность — чек-лист

- [ ] Сменён `admin/admin`, включена 2FA.
- [ ] Задан секретный Web Base Path (и подписка — по секретному пути).
- [ ] UFW включён, лишних портов нет: `ufw status`.
- [ ] Бэкапы делаются и **забираются** с сервера.
- [ ] На нодах панель закрыта (`node-hardening.sh`), API-токены нод хранятся как пароли.
- [ ] Sub-ссылки и QR не публикуются — это полный доступ.

## 11. Мульти-ноды: одна панель — несколько серверов

Начиная с v3.0 панель умеет управлять другими серверами с 3x-ui как **нодами**: инбаунды деплоятся с мастера, подписка клиента собирается из всех серверов, где он привязан. Клиенты видят все сервера в одной подписке и сами подхватывают новые при её обновлении.

**Роли:**
- **Мастер** — только панель и подписки (control plane; VPN-инбаундов на нём нет, хватит маленького VPS).
- **Нода** — чистый VPN-сервер: `install.sh` + `node-hardening.sh`. Веб-панель ноды наружу не торчит (только API-порт, и тот — только для IP мастера).

**Подключение ноды (один раз) — автоматически:**
1. На ноде: `bash scripts/install-node.sh <IP_МАСТЕРА>` — поставит всё, закроет панель, вольёт RU-фильтр,
   создаст API-токен и напечатает его (также лежит в `/root/.node-info` на ноде).
2. На мастере: `bash scripts/attach-node.sh <IP_НОДЫ> <TOKEN> [INBOUND_ID] [NAME]` — зарегистрирует ноду и развернёт на ней
   копию Reality-инбаунда с теми же клиентами (NAME — читаемое имя ноды и инбаунда, напр. `FR-138`;
   чтобы задать NAME без INBOUND_ID, передай третьим аргументом пустую строку: `""`). Скрипт идемпотентен:
   повторный запуск не дублирует ноду. Подписки подхватят сервер сами.

Ручной вариант (если скрипты недоступны): `install.sh` + `node-hardening.sh`, токен в Settings → API Tokens,
«Nodes» → «Add Node», инбаунд с выбором ноды в поле **Node**.

**Добавление родственника в мульти-нодах:** создай клиента с уникальным `subId` и привяжи его к **каждому** инбаунду (кнопка «Привязанные входящие» → выбрать все) — одна sub-ссылка будет содержать все ноды.

**Сценарий «IP ноды заблокирован»:**
1. Купи новый VPS и разверни ноду: `bash scripts/install-node.sh <IP_МАСТЕРА>` (RU-фильтр уже внутри).
2. На мастере: `bash scripts/attach-node.sh <IP_НОДЫ> <TOKEN>`, удали старую ноду в «Nodes».
3. Готово: клиенты получат новый сервер при обновлении подписки (приложения делают это сами по расписанию). Ни одной перераздачи ссылок.

**Сценарий «IP мастера заблокирован»** (в режиме с доменом, раздел 12): смени A-запись домена на новый IP — sub-ссылки продолжат работать.

## 12. Домен и HTTPS для панели и подписок

В режиме с доменом панель и подписки живут за nginx по HTTPS (`https://<домен>/<секретный путь>/`); 443 при этом занимает nginx, поэтому VPN-инбаундов на мастере нет — он чистый control plane, а Reality живёт только на нодах (у них 443 свободен). Если когда-нибудь захочешь свой инбаунд и на мастере — сажай его на отдельный порт (например 8443) и передай его в `setup-web.sh` шестым аргументом.

**Почему DNS-01, а не обычный выпуск certbot:** у части хостеров входящий 80 порт фильтруется для чужих сетей — Let's Encrypt не может дотянуться по HTTP-01. DNS-01 подтверждает домен через TXT-запись и не требует открытых портов. Хуки для Porkbun лежат в `scripts/certbot/`.

**Настройка (один раз, на мастере):**
1. Создай у регистратора A-запись: `<поддомен> → <IP мастера>` (например `abs.example.com`).
2. Включи у домена доступ по API (у Porkbun: Domain Management → ⚙ → API Access) и положи ключи в `/root/.porkbun-keys` на мастере (chmod 600):
   ```
   PORKBUN_APIKEY="pk1_..."
   PORKBUN_SECRET="sk1_..."
   ```
3. В панели (Panel Settings): задай **Web Domain** = твой домен, **Reverse Proxy URI / subURI** = `https://<домен><subPath>`, **subListen** = `127.0.0.1` (sub-сервер слушает только localhost, наружу его отдаёт nginx). Рекомендуется также задать Web Base Path.
4. Скопируй хуки на мастер: `cp scripts/certbot/porkbun-*.sh /usr/local/bin/ && chmod 700 /usr/local/bin/porkbun-*.sh`.
5. Запусти `bash scripts/setup-web.sh <домен> <webBasePath> <subPath> [subJsonPath] [subClashPath]` — скрипт поставит nginx, настроит прокси, выпустит сертификат и поправит UFW (порт Reality мастера откроется, только если передать его шестым аргументом — по умолчанию на мастере его нет).
6. Продление автоматическое (`certbot.timer`, хуки привязаны к сертификату). Проверка: `certbot renew --dry-run`.

**Важно:** после включения Web Domain панель отвечает только на запросы с заголовком `Host: <домен>` — обращаться к ней напрямую по IP перестанет работать (это защита, так и задумано).

## 14. Телеграм-бот: ссылки и QR без твоего участия

Бот `@AndyFam1313_bot` выдаёт каждому его sub-ссылку и QR по кнопке, показывает статус нод
и у глав семей — ссылки членов семьи. Родственник больше не просит «скинь ссылку»:
у него всегда под рукой актуальная. Живёт на мастере в отдельном контейнере
(`docker-compose.bot.yml`), **не открывает ни одного входящего порта** (long polling),
панельную БД читает read-only. Мутаций клиентов не делает — добавление/отключение людей
по-прежнему в панели.

**Установка (мастер, один раз):**
1. Создай бота в @BotFather, положи токен в `/root/.tg-bot-token` (chmod 600) —
   install-скрипт скопирует его в `/opt/3x-ui/bot/tg-bot-token` (владелец — uid контейнера).
2. `bash scripts/install-bot.sh` — соберёт и запустит контейнер `tg-vpn-bot`
   и напечатает bootstrap-ссылку.
3. Открой bootstrap-ссылку от себя → станешь админом бота; затем `/bindme <твой email>`
   привяжет бота к твоему профилю панели.

**Привязка родных (по шагам):**
1. `/sync` — реестр клиентов из панели.
2. `/family <email> <семья> [head|member]` — зачислить в семью (повторное зачисление
   с другим именем семьи = перемещение); `head` назначает главой, `member` снимает главу;
   `/family <email> -` — убрать из семьи. Семьи из email-префиксов автоматически не выводятся —
   назначаются вручную. **Глава семьи** сам управляет своей семьёй: может зачислять в свою семью
   и убирать из неё (`/family` без флага head, только со своим именем семьи), но не может трогать
   чужие семьи, назначать глав или убирать главу — это админ.
3. `/invite <email>` → перешли человеку ссылку из ответа
   (`t.me/<бот>?start=<код>`, одноразовая, живёт 7 дней). При смене телефона:
   `/bind @username <email>` — бот привяжет при первом сообщении человека.

**Кнопки у всех:** «Моя ссылка», «QR-код», «Ноды и статус» (живость серверов с мастера —
не путать с реальным пингом с телефона), «Моя семья» (только у главы), «Помощь»
(импорт подписки в Happ/v2rayNG). То же самое работает командами `/link`, `/qr`, `/nodes`,
`/myfamily`, `/help` — при вводе `/` телеграм показывает подсказки; у администратора
в подсказках дополнительно видны служебные команды.

**Инлайн-интерфейс (основной способ управления):**
- Админу — кнопка «Админка»: клиенты (список-страницы → карточка: пригласить, привязать
  телеграм, назначить семью/новая семья), семьи (состав, главы, добавление из числа
  нераспределённых), активные инвайты с отзывом, аудит, синхронизация с панелью.
  Ручной ввод нужен только для имени новой семьи и контакта привязки (с «Отменой»).
- Главе семьи — «Моя семья»: ссылки/QR членов, кнопки «➕ Добавить члена» (из
  нераспределённых) и «✕ убрать».
- Текстовые команды (/clients, /invite, /family, /bind, /who, /audit, /sync) продолжают
  работать и дублируют инлайн-интерфейс.

**Важно про пересылку:** sub-ссылку и QR нельзя отправлять через российские сервисы
и мессенджеры (ВКонтакте, Одноклассники и т.п.) — там они становятся видимыми третьим
лицам, и домен подписки могут заблокировать. Только лично или через Telegram.
**Команды админа:** `/clients` (все клиенты панели с семьями и привязкой), `/invite`, `/invites`,
`/bind`, `/bindme`, `/family`, `/families`, `/who`, `/audit`, `/sync`.
